## 42.2 高频面试题 30 题

### 基础题

**Q1：GORM 零值陷阱是什么？如何避免？**
> A：GORM 在 Updates 和 Where 中会跳过零值字段（int 的 0、string 的 ""、bool 的 false）。解决方案：①用指针类型；②用 Map；③用 Select 强制指定字段。

**Q2：Save vs Update vs Updates 的区别？**
> A：Save 全字段保存（根据主键判断 Insert/Update）；Update 更新单列；Updates 更新多列（struct 零值跳过，map 不跳过）。日常推荐 Update/Updates，Save 有覆盖风险。

**Q3：First vs Take vs Last vs Find 的区别？**
> A：First 按主键升序第一条；Take 随机一条；Last 按主键降序最后一条；Find 取所有。找不到时前三者返回 ErrRecordNotFound，Find 返回空切片不报错。

**Q4：软删除原理？如何查询已删除记录？**
> A：软删除设置 deleted_at 时间戳而非真正 DELETE。普通查询自动过滤（WHERE deleted_at IS NULL）。`Unscoped()` 查询所有（包括已删除）。`Unscoped().Delete()` 硬删除。

**Q5：AutoMigrate 能做什么、不能做什么？**
> A：能创建表、添加列、添加索引。不能删除列、修改列名、删除索引。设计原则：只做加法不做减法，保护数据安全。

### 查询题

**Q6：N+1 问题是什么？如何解决？**
> A：查询 N 条主记录后，循环中逐条查关联 → N+1 条 SQL。解决方案：Preload（2条SQL）或 Joins（1条SQL）。

**Q7：Preload 和 Joins 的区别？**
> A：Preload 用多条 SQL 加载关联，自动填充结构体，适合纯展示。Joins 用一条 SQL（JOIN），适合需要关联条件过滤的场景。一对多/多对多必须用 Preload。

**Q8：如何实现分页查询？**
> A：`db.Limit(pageSize).Offset((page-1)*pageSize).Find()` + `db.Count(&total)`。大偏移量（翻页太深）可用游标分页（`WHERE id > lastID`）。

**Q9：Where(struct) 和 Where(map) 有什么区别？**
> A：struct 零值被跳过（int 的 0、string 的 ""），map 不跳过。查询包含零值的条件用 map 或字符串条件。

**Q10：如何防止 SQL 注入？**
> A：始终使用 `?` 占位符（参数化查询），不拼接字符串。GORM 的 Where/Find/Create 等方法默认安全。Raw/Exec 也要用占位符。ORDER BY 等无法占位的参数要白名单校验。

### 关联题

**Q11：HasOne vs BelongsTo 选哪个？**
> A：谁"归属"于对方 → BelongsTo（外键在自己）；谁"拥有"对方 → HasOne（外键在对方）。User BelongsTo Company（外键 company_id 在 users），User HasOne CreditCard（外键 user_id 在 credit_cards）。

**Q12：多对多中间表有额外字段怎么办？**
> A：手动定义中间表 Model + `SetupJoinTable`，然后直接操作中间表。

**Q13：Association 模式的常用操作？**
> A：Append（追加）、Delete（删除关联）、Replace（替换）、Clear（清空）、Count（统计）。注意 Delete 只解除关联不删除记录。

### 事务题

**Q14：如何正确使用事务？**
> A：推荐 `db.Transaction(func(tx *gorm.DB) error { ... return nil })`，return nil 提交，return error 回滚。闭包内必须用 tx 不能用 db。

**Q15：悲观锁 vs 乐观锁？**
> A：悲观锁（SELECT FOR UPDATE）锁住行，适合冲突多的场景（如库存扣减）。乐观锁（版本号 + RowsAffected 判断）不锁行，适合冲突少、读多写少的场景。

### 性能题

**Q16：如何优化批量插入？**
> A：CreateInBatches 分批插入 + 事务包裹 + SkipDefaultTransaction + PrepareStmt。

**Q17：连接池怎么配置？**
> A：MaxOpenConns（25-100）、MaxIdleConns（~10）、ConnMaxLifetime（3-5min）、ConnMaxIdleTime（1min）。生产必须配置上限，避免连接数爆炸。

## 42.3 场景设计题

**场景1：设计博客系统 GORM 模型**
> User (HasMany Articles, HasMany Comments), Article (BelongsTo User, HasMany Comments, Many2Many Tags), Comment (BelongsTo User, BelongsTo Article), Tag (Many2Many Articles)

**场景2：转账操作的事务实现**
> 事务中：A 扣钱 → B 加钱 → 记录日志。任何一步失败 → 全部回滚。加悲观锁防并发。

**场景3：千万级数据的分页优化**
> OFFSET 过大 → 用游标分页（WHERE id > lastID LIMIT 10），或子查询定位 + 覆盖索引。

## 42.4 选型指南

| 方案 | 适用场景 |
|------|---------|
| GORM | 大多数 Go Web 项目，功能全、社区大 |
| sqlx | 喜欢手写 SQL，只需要薄封装 |
| sqlc | 强 SQL 能力团队，需要极高类型安全 |
| ent | 大型项目，需要 Schema 驱动的代码生成 |
