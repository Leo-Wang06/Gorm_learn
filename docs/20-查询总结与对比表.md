## 20.1 查询方法速查表

### 获取记录

| 方法 | SQL | 找不到时 | 备注 |
|------|-----|---------|------|
| `First(&user)` | `ORDER BY primary_key LIMIT 1` | ErrRecordNotFound | 按主键升序第一条 |
| `First(&user, id)` | `WHERE id=? LIMIT 1` | ErrRecordNotFound | 主键快捷查询 |
| `Take(&user)` | `LIMIT 1` | ErrRecordNotFound | 不附加主键排序；数据库返回哪条由执行计划决定，顺序不作保证 |
| `Last(&user)` | `ORDER BY primary_key DESC LIMIT 1` | ErrRecordNotFound | 按主键降序第一条 |
| `Find(&users)` | `SELECT *` | nil，空切片 | 所有记录 |
| `Find(&users, ids)` | `WHERE id IN ?` | nil，空切片 | IN 查询 |

### 条件查询

| 方法 | 示例 |
|------|------|
| `Where(string)` | `db.Where("name = ?", "张三")` |
| `Where(struct)` | `db.Where(&User{Name:"张三"})` ⚠️ 零值跳过 |
| `Where(map)` | `db.Where(map[string]interface{}{"name":"张三","age":0})` ✅ 零值不跳过 |
| `Not()` | `db.Not("age = ?", 25)` |
| `Or()` | `db.Where("a=1").Or("b=2")` |
| `Where().Where()` | AND 链式组合 |

### 排序与分页

| 方法 | 示例 |
|------|------|
| `Order("col desc")` | `db.Order("age desc, name asc")` |
| `Limit(n)` | `db.Order("id ASC").Limit(10)`（分页时配合稳定排序） |
| `Offset(n)` | `db.Order("id ASC").Offset(20)`（分页时配合稳定排序） |
| `Limit(-1)` | 取消之前的 Limit |

### 字段选择与聚合

| 方法 | 示例 |
|------|------|
| `Select("a", "b")` | `db.Select("name, age").Find(&users)` |
| `Select("SUM(x)")` | `db.Select("AVG(age)").Scan(&avg)` |
| `Group("col")` | `db.Group("city").Find(&results)` |
| `Having("cond")` | `db.Having("COUNT(*) > ?", 5)` |
| `Distinct("col")` | `db.Distinct("status").Pluck("status", &list)` |

### Join

| 方法 | 示例 |
|------|------|
| `Joins("LEFT JOIN ...")` | `db.Joins("LEFT JOIN c ON u.cid = c.id")` |
| `Joins("Relation")` | `db.Joins("Company")` 利用关联定义 |
| `InnerJoins("Relation")` | `db.InnerJoins("Company")` 内连接 |

### 其他

| 方法 | 示例 |
|------|------|
| `Count(&n)` | `db.Model(&User{}).Count(&total)` |
| `Pluck("col", &slice)` | `db.Pluck("name", &names)` |
| `Scan(&struct)` | `db.Raw("...").Scan(&custom)` |
| `Scopes(s1, s2)` | `db.Scopes(ActiveUsers, Paginate(1,10))` |

## 20.2 方法选择决策树

```
你想做什么？
│
├─ 查一条记录
│   ├─ 知道主键 → db.First(&user, id)  ← 最简洁
│   ├─ 知道条件 → db.Where(...).First(&user)
│   └─ 任意一条  → db.Take(&user)
│
├─ 查多条记录
│   ├─ 查全部     → db.Find(&users)
│   ├─ 带条件     → db.Where(...).Find(&users)
│   ├─ 需要分页   → db.Order("id ASC").Scopes(Paginate(1,10)).Find(&users)（稳定排序）
│   ├─ 需要排序   → db.Order("col desc").Find(&users)
│   └─ 需要分组   → db.Select("col, COUNT(*)").Group("col").Scan(&result)
│
├─ 只查一列
│   └─ db.Pluck("col", &slice)
│
├─ 只计数
│   └─ db.Model(&User{}).Count(&total)
│
├─ 多表关联
│   ├─ 需要过滤关联表 → db.Joins("Relation").Where(...).Find(&users)
│   └─ 纯展示关联数据 → db.Preload("Relation").Find(&users)  (Phase 5)
│
└─ GORM API 不够用
    └─ db.Raw("SQL").Scan(&result)
```

## 20.3 查询性能参考

| 查询类型 | 影响性能的因素 | 优化/验证建议 |
|---------|----------------|-------------|
| 主键查询 | 数据库位置、缓存、网络、锁等待、返回列大小 | 检查执行计划与端到端延迟；不能承诺固定毫秒数 |
| WHERE 索引列 | 选择性、覆盖情况、回表、统计信息 | 用 `EXPLAIN` 验证实际索引与扫描行数 |
| WHERE 无索引列 | 表规模、过滤比例、是否能建立合适索引 | 评估索引收益及写入/存储成本 |
| `LIKE '%x%'` | 前导通配符通常难以用普通 B-tree 索引 | 按数据库与语言需求评估全文索引等方案 |
| 大 `OFFSET` 分页 | 排序、索引、偏移量、回表成本 | 评估 Keyset；需要随机跳页时结合实际执行计划设计 |
| 多表 JOIN | 连接顺序、基数估算、索引、返回行数 | 查看 `EXPLAIN`；确保连接键与过滤条件合理 |
| `GROUP BY` | 分组基数、排序/临时表、索引与数据量 | 先测量瓶颈，再考虑索引、预聚合或汇总表 |
| `COUNT(*)` | 存储引擎、过滤条件、隔离级别、索引和表规模 | InnoDB 通常需扫描可用索引来获得符合语义的精确计数；以执行计划和实测为准 |

## 20.4 GORM vs 原生 SQL 代码量对比

### 简单查询

```go
// 原生 SQL（假设 db 为 *sql.DB）
rows, err := sqlDB.Query("SELECT id, name, age, email, created_at, updated_at FROM users WHERE age > ?", 18)
if err != nil {
	return err
}
defer rows.Close()

var users []User
for rows.Next() {
	var u User
	if err := rows.Scan(&u.ID, &u.Name, &u.Age, &u.Email, &u.CreatedAt, &u.UpdatedAt); err != nil {
		return err
	}
	users = append(users, u)
}
if err := rows.Err(); err != nil {
	return err
}

// GORM（等价查询；错误仍需处理）
if err := gormDB.Where("age > ?", 18).Find(&users).Error; err != nil {
	return err
}
```

> 📌 两种实现的代码量会随错误处理、模型字段和封装方式变化；这里比较的是查询与扫描样板代码，不代表 GORM 可以省略错误处理。

### 带分页的查询

```go
// 原生 SQL（示意：生产代码需检查每个错误，并列出所需列）
var total int64
if err := sqlDB.QueryRow("SELECT COUNT(*) FROM users WHERE age > ?", 18).Scan(&total); err != nil {
	return err
}
rows, err := sqlDB.Query("SELECT id, name, age FROM users WHERE age > ? ORDER BY id ASC LIMIT 10 OFFSET 20", 18)
if err != nil {
	return err
}
defer rows.Close()
// ...逐列 Scan，并检查 rows.Err()...

// GORM（等价，分页使用稳定排序）
baseQuery := gormDB.Model(&User{}).Where("age > ?", 18)
if err := baseQuery.Count(&total).Error; err != nil {
	return err
}
if err := baseQuery.Order("id ASC").Limit(10).Offset(20).Find(&users).Error; err != nil {
	return err
}
```

### 复杂关联查询

```go
// 原生 SQL（示意：生产代码需检查 Query、Scan 与 rows.Err()）
rows, err := sqlDB.Query(`
	SELECT u.id, u.name, COUNT(o.id) AS order_count, COALESCE(SUM(o.amount), 0) AS total
	FROM users u
	LEFT JOIN orders o ON u.id = o.user_id
	WHERE u.created_at > ?
	GROUP BY u.id, u.name
	HAVING COUNT(o.id) > 0
	ORDER BY total DESC, u.id ASC
	LIMIT 10
`, startDate)
if err != nil {
	return err
}
defer rows.Close()
// ...定义结构体，逐列 Scan 并检查 rows.Err()...

// GORM（等价；假设 users.id 是主键，聚合列名使用显式别名）
type UserStats struct {
	ID         uint
	Name       string
	OrderCount int64
	Total      float64
}
var stats []UserStats
err := gormDB.Model(&User{}).Select(`
	users.id AS id, users.name AS name,
	COUNT(orders.id) AS order_count,
	COALESCE(SUM(orders.amount), 0) AS total
`).
Joins("LEFT JOIN orders ON users.id = orders.user_id").
Where("users.created_at > ?", startDate).
Group("users.id, users.name").
Having("COUNT(orders.id) > ?", 0).
Order("total DESC, users.id ASC").
Limit(10).
Scan(&stats).Error
if err != nil {
	return err
}
```

## 20.5 常见查询模式汇总

### 模式1：分页查询（最常用）

```go
func ListUsers(db *gorm.DB, page, pageSize int, filters map[string]interface{}) ([]User, int64, error) {
	var users []User
	var total int64

	// map 的 key 是列名，不能用 ? 占位符绑定；仅接受已知字段白名单。
	allowedFilters := map[string]bool{"status": true, "city": true}
	query := db.Model(&User{})
	for key, value := range filters {
		if !allowedFilters[key] {
			return nil, 0, fmt.Errorf("不支持的筛选字段: %s", key)
		}
		query = query.Where(key+" = ?", value)
	}

	if err := query.Count(&total).Error; err != nil {
		return nil, 0, err
	}
	if err := query.Scopes(Paginate(page, pageSize)).
		Order("id DESC").
		Find(&users).Error; err != nil {
		return nil, 0, err
	}
	return users, total, nil
}
```

### 模式2：条件筛选

```go
func SearchUsers(db *gorm.DB, req SearchRequest) ([]User, error) {
	var users []User
	query := db.Model(&User{})

	if req.Keyword != "" {
		query = query.Where("name LIKE ? OR email LIKE ?",
			"%"+req.Keyword+"%", "%"+req.Keyword+"%")
	}
	if req.Status != "" {
		query = query.Where("status = ?", req.Status)
	}
	if req.MinAge > 0 {
		query = query.Where("age >= ?", req.MinAge)
	}

	err := query.Find(&users).Error
	return users, err
}
```

### 模式3：聚合统计

```go
type StatsResult struct {
	Label string
	Count int64
}

func CountByStatus(db *gorm.DB) ([]StatsResult, error) {
	var results []StatsResult
	err := db.Model(&User{}).
		Select("status as label, COUNT(*) as count").
		Group("status").
		Scan(&results).Error
	return results, err
}
```

### 模式4：关联查询

```go
func GetUserWithCompany(db *gorm.DB, userID uint) (*UserWithCompany, error) {
	var result UserWithCompany
	err := db.Model(&User{}).
		Select("users.*, companies.name as company_name").
		Joins("LEFT JOIN companies ON users.company_id = companies.id").
		Where("users.id = ?", userID).
		Scan(&result).Error
	return &result, err
}
```

## 本章小结

本章是 Phase 4 的终点站。回顾一下你已经掌握的查询技能：

- ✅ 单条查询：First、Take、Last、Find
- ✅ 条件查询：Where（字符串/结构体/Map）、Not、Or
- ✅ 排序分页：Order、Limit、Offset
- ✅ 字段选择：Select、Omit
- ✅ 聚合统计：Group、Having、`Count()`，以及通过 `Select` + `Scan` 使用的 `SUM/AVG/MAX/MIN`
- ✅ 连接查询：Joins、InnerJoins
- ✅ 子查询：WHERE/ FROM/ SELECT 中的子查询
- ✅ Scope 封装：可复用的查询逻辑
- ✅ 原生 SQL：Raw + Scan
- ✅ 调试工具：DryRun、Debug、Logger

从下一章开始，进入 Phase 5——GORM 最强大的功能：关联关系。
