## 38.1 GORM 插件架构

GORM 通过插件接口实现可扩展性。插件的 `Initialize` 通常负责注册 Callback、Clause 或其他会话行为；初始化失败应返回错误：

```go
type Plugin interface {
	Name() string
	Initialize(*gorm.DB) error
}

// 注册插件
if err := db.Use(plugin); err != nil {
	panic(err)
}
```

### 内置/社区插件

| 插件 | 功能 |
|------|------|
| DBResolver | 读写分离、多数据源 |
| Sharding | 分库分表 |
| OptimisticLock | 乐观锁（社区插件，需单独安装并按其文档配置） |
| Prometheus | 监控指标（社区插件，需单独安装） |
| Hints | 索引提示（GORM 内置 clause，通常不需要单独安装插件） |

## 38.2 DBResolver：读写分离

安装：

```bash
go get gorm.io/plugin/dbresolver
```

`gorm.Open` 传入的连接会作为默认数据源；`Sources`/`Replicas` 用于覆盖或扩展 resolver 配置。

```go
import "gorm.io/plugin/dbresolver"

db, err := gorm.Open(mysql.Open(masterDSN), &gorm.Config{})
if err != nil {
	panic(err)
}

// db 已经使用 masterDSN 作为默认连接；这里只注册从库。
if err := db.Use(dbresolver.Register(dbresolver.Config{
	Replicas: []gorm.Dialector{
		mysql.Open("slave1_dsn"),
		mysql.Open("slave2_dsn"),
	},
	Policy: dbresolver.RandomPolicy{}, // 随机选择从库
})); err != nil {
	panic(err)
}

// 写操作 → 自动使用主库
db.Create(&user)

// 读操作 → 自动使用从库
db.Find(&users)

// 强制从主库读取
if err := db.Clauses(dbresolver.Write).Find(&users).Error; err != nil {
	panic(err)
}
```

## 38.3 自定义 Plugin

```go
import (
	"reflect"

	"gorm.io/gorm"
)

// 自动填充创建人的插件。示例模型需要有可写的 CreatedBy 字段。
type AuditPlugin struct{}

type auditable interface {
	// 这里只用于说明业务模型约定；实际字段写入仍由回调完成。
}

func (p *AuditPlugin) Name() string {
	return "audit_plugin"
}

func (p *AuditPlugin) Initialize(db *gorm.DB) error {
	return db.Callback().Create().Before("gorm:create").Register(
		"audit:before_create",
		func(tx *gorm.DB) {
			if tx.Statement.Schema == nil {
				return
			}
			field := tx.Statement.Schema.LookUpField("CreatedBy")
			if field == nil || !field.Creatable {
				return
			}
			// 此处只演示单个 struct；生产插件还应处理批量创建和指针层级。
			if tx.Statement.ReflectValue.Kind() == reflect.Struct {
				if err := field.Set(tx.Statement.Context, tx.Statement.ReflectValue, "system"); err != nil {
					tx.AddError(err)
				}
			}
		},
	)
}

// 使用
if err := db.Use(&AuditPlugin{}); err != nil {
	panic(err)
}
// 之后所有 Create 操作都会尝试填充 CreatedBy
```

## 38.4 Callback 系统简介

GORM 内部的 CRUD 流程由 Callback 组织。你可以注册自己的 Callback 来观察或修改流程，但回调名称和执行顺序依赖 GORM 版本；不要覆盖内置回调名，注册时使用项目唯一名称：

```go
import "log"

// 注册一个 Callback
if err := db.Callback().Create().Before("gorm:create").Register("my_callback", func(db *gorm.DB) {
	// 在 Create 之前执行
	log.Println("即将执行 INSERT")
}); err != nil {
	panic(err)
}

// Callback 类型
db.Callback().Create()   // 创建
db.Callback().Update()   // 更新
db.Callback().Delete()   // 删除
db.Callback().Query()    // 查询
db.Callback().Row()      // Row
db.Callback().Raw()      // Raw
```

## 38.5 常用社区插件

```bash
# DBResolver（读写分离）
go get gorm.io/plugin/dbresolver

# OptimisticLock（乐观锁）
go get gorm.io/plugin/optimisticlock

# Prometheus（监控）
go get gorm.io/plugin/prometheus

# Sharding（分表）
go get gorm.io/sharding
```

> 这些模块的版本、配置字段和支持的数据库可能独立于 `gorm.io/gorm` 变化。安装后应查看对应模块的 README/API，并锁定版本；`Hints` 属于 GORM 的 clause 能力，通常直接使用 `gorm.io/hints`，不是这里列出的独立插件。

## 本章小结

- GORM 通过 Plugin 接口实现扩展性
- DBResolver 实现读写分离（主库写、从库读）
- 自定义 Plugin 可以拦截操作流程
- Callback 是 GORM 内部的操作钩子
